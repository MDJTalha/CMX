TRANSPARENCY BY DESIGN

Trust & evidence

Understand what the current CMX engine does—and what it does not claim.

✓

Explicit requirements

Capability keys and requirement weights are provided explicitly. The core engine does not silently infer semantic matches from free text.

IMPLEMENTED
⌕

Evidence status

Evidence is labeled verified, user-provided, estimated, assumed or unknown. The interface never treats a user-entered claim as independently verified.

IMPLEMENTED
!

Uncertainty handling

Unknown requirements and missing cost data remain distinct from confirmed failures. Results may be provisional or require more information.

IMPLEMENTED
⌁

Authorization boundary

Assessment evaluation requires an authorized bearer credential with the assessment:write permission. Credentials are never stored in browser persistence.

API ENFORCED
↗

Documented match score

The score describes documented requirement coverage. It is not a confidence estimate, success probability, independent audit or endorsement.

EXPLAINABLE
◌

Current limitations

No built-in web discovery, source validation, LLM integration, server-side assessment history or provider catalogue is exposed in this version.
